Nobody remembers why it is shaped like this.

You inherit a 300,000-line Spring monolith with an Angular front end. The architecture diagram on the wiki is four years old. The people who designed the data model have left. Every change is a guess about what else it touches.

Most tools either draw boxes that look confident and are wrong, or give you a thousand lint warnings. Stratigraph is built on one rule: static analysis produces the facts, and nothing is ever asserted without a citation. When it could not see something — no JDK, an unread module, a type from a jar — it says so on the page, and withholds a view rather than draw a partial one as if it were whole.

What you get

One command, a map you can defend.

Architecture that matches the build

C4 diagrams at context, container and component level. A container is a real deployable — a Spring Boot app, a WAR, an Angular or Nx application — proved by its build file or main class. Aggregator and BOM poms are grouping, not boxes. Test code is left out and counted.

The data model as the database has it

Tables, columns and foreign keys from Liquibase, Flyway and SQL DDL, overlaid with JPA mappings — default naming strategies, inheritance, embedded ids, @MappedSuperclass. Where the classes and the migrations disagree, that is a finding.

Who reads and writes each table

Spring Data repositories, JPQL and native @Query, and JDBC SQL become read/write edges, so “what touches orders?” has a cited answer.

The whole HTTP surface

Spring MVC, JAX-RS, custom meta-annotations, paths built from constants, API-first controllers joined to their OpenAPI spec, Koa and Express routes — and Angular calls linked to the endpoints they hit.

Risk from history, not size

Hotspots rank recent change in source files, scaled by complexity — never lockfiles or generated code. Co-change coupling finds files that move together with no dependency between them. Knowledge silos flag files one person owns that the rest of the code depends on.

Findings with evidence

Package cycles with the shortest path and the lines that close it, schema drift, hidden coupling, bus factor. Each finding cites the edges, files or commits it rests on; one that cannot is not shown.

Coverage on every view

“Built from 412 of 1,030 Java files; the Java extractor did not run: no JDK 17+.” Every diagram, ranking and answer states its coverage. Below 50%, a view is withheld with the reason instead of drawn.

An MCP server for AI agents

Point Claude Code or any MCP client at the fact store: what_breaks_if, who_knows, where_is_table_written, find_callers, check_cycle and more — each answer cited and carrying its coverage.

Fits in CI

--format json on every command, --fail-on severity gates, and stratigraph diff to fail a build only on findings that are new — the gate a repository with existing debt can switch on today.

The report

A static HTML report you can hand to anyone.

Self-contained, no server, no scripts, prints cleanly. These are real reports of public repositories, generated by stratigraph scan.

How it works

Facts first. Interpretation is labelled.

  1. 1

    Extract

    Separate extractors parse Java/Kotlin (OpenRewrite), TypeScript/Angular (the TS compiler API) and migrations, emitting facts as NDJSON.

  2. 2

    Store

    Nodes and edges land in a local SQLite fact store, each with a file and line. Every file gets a role — source, test, generated, migration, lockfile.

  3. 3

    Mine history

    git log gives recent change, authorship and co-change, with bulk sweeps and .git-blame-ignore-revs left out.

  4. 4

    Analyse

    Cycles, clusters, hotspots, schema drift and coupling become findings with citations. An optional model may name clusters — marked as inference.

  5. 5

    Present

    HTML report, Mermaid and Structurizr diagrams, findings.md, JSON, and an MCP server — all projections of the same stored facts.

A confidently wrong dependency map is worse than no map. If a relationship cannot be cited, the answer is “no evidence found” — not a plausible guess.

For agents

Ask the codebase, get citations back.

Run stratigraph mcp and connect it to Claude Code, Cursor or any MCP client. Thirteen read-only tools answer structural questions from the stored facts — and every answer ends with the coverage of the view it came from, so the agent knows when an empty answer means “unknown”.

  • what_breaks_if — transitive dependents, the tests that reach them, the endpoints they serve
  • who_knows — authors, share and recency, from git
  • where_is_table_written — repositories, queries and SQL, cited
  • explain_hotspot — every number behind a file's rank

Get started

Five minutes to your first map.

# Node 18.18+; a JDK 17+ for Java code
npm install -g stratigraph
stratigraph doctor              # what this machine can analyse
stratigraph fetch-extractor     # the Java extractor, checksum-verified

# the whole pipeline, then open the report
stratigraph scan path/to/repo --no-llm
open stratigraph-report/index.html

# let your agent query it
stratigraph mcp --repo path/to/repo

Prefer containers? docker run --rm -v "$PWD:/repo:ro" ghcr.io/imashishsharma/stratigraph doctor

Questions

Does Stratigraph send my code anywhere?

No. Extraction and history mining run entirely on your machine with no network access. The optional interpretation layer sends structural metadata to a model API only if you configure a key, and never raw source unless you pass --send-source. Everything works with --no-llm.

Which languages and frameworks does it understand?

Java and Kotlin with Spring, Spring Boot, JPA/Hibernate, Spring Data and JAX-RS; Liquibase, Flyway and SQL DDL; TypeScript and Angular — NgModules, standalone components, routes and DI; OpenAPI specs; Koa and Express routes.

Do I need a JDK or a working build?

Only for the Java half, which needs a JDK 17+. Stratigraph never runs your build. If your Maven dependencies are already in the local cache it uses them offline for richer types; otherwise it reads source only — and says so in every view.

How is this different from SonarQube or Structurizr?

SonarQube reports rule violations file by file; Structurizr draws the architecture you describe. Stratigraph derives the architecture, data model and API from the code and its history, cites every element, and tells you how much of the code each view covers.

Is it free?

Yes — open source under Apache 2.0, on npm and GitHub.
